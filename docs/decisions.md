| D22 | How does the server check Google's ID token, and where does the sign-in state live? | PyJWT with `cryptography` (MIT; Apache-2.0 or BSD) verifies the RS256 signature against Google's published keys, plus audience, issuer, expiry and nonce; the keys are cached for an hour and refetched at most once a minute on an unknown key id. The code exchange and key fetch use stdlib `urllib` (no HTTP client dependency). State, nonce and PKCE verifier live in a signed, HttpOnly, 10-minute `__Host-` cookie, not a table, and work once. All cookies are `__Host-` prefixed, Secure, HttpOnly, SameSite=Lax. Also: Google is always asked to show the account chooser (`prompt=select_account`); a failed round trip lands on `/signin?error=failed`, a refusal on `/signin/refused`, which reads the refused address from a signed 10-minute cookie through `GET /auth/refusal` (never from the URL); the signed-in person is `GET /api/me` (D19 paths); a session's end moves out at most once an hour; when Google reports an email another person already has, the stored email is kept; `POST /auth/signout` already requires Origin = `TAZKO_WEB_ORIGIN` (M1-05 extends this to every write); in development `TAZKO_PUBLIC_URL` is the Vite server so cookies land on the web host. | M1 | proposed |
