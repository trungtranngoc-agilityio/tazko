## Done when

Each line of the build plan's M1 section as scenarios, with the test that proves it.
Backend tests live under `backend/tests/`; e2e under `tests/e2e/`.

### M1-01 · Walking skeleton
- Given the API runs, when `GET /health`, then 200 `{"status":"ok"}` — integration `test_http.py::test_health_returns_200`.
- Given another origin, when a CORS preflight arrives, then no allow-origin header — `test_http.py::test_cors_ignores_other_origins`.
- The web page loads and reaches the API — e2e `health.spec.ts`.

### M1-02 · Config and commands
- Given `TAZKO_ENV=production` and no Google client id, when settings load, then the error names `TAZKO_GOOGLE_CLIENT_ID` — unit `test_config.py::test_production_requires_google_client`.
- Given production, when `TAZKO_PUBLIC_URL` or `TAZKO_WEB_ORIGIN` is not https, then a clear error — `test_production_requires_https_urls`.
- Given `TAZKO_SECRET` shorter than 32 characters, then the error names it — `test_short_secret_is_refused`.
- Given an empty `TAZKO_SECRET`, when the secret is first needed, then a random `secret` file (mode 600) is made in the data folder and reused afterwards — `test_secret.py`.
- Given `TAZKO_SMTP_HOST` without `TAZKO_MAIL_FROM`, then the error names `TAZKO_MAIL_FROM` — `test_smtp_needs_mail_from`.
- `tazko admin --email X` creates or promotes X to super admin and writes an audit row (lands with M1-03, which brings `control.db`) — `test_cli.py::test_admin_creates_a_super_admin`, `test_admin_promotes_an_existing_person`.
- `backup` and `check` exist and say they arrive in M1-08 — `test_cli.py::test_unfinished_commands_fail_with_the_task_id`.

### M1-03 · Databases
- Given a new data folder, when the app starts, then `control.db` exists at the latest `user_version` with WAL and foreign keys on — `test_db.py::test_new_database_is_migrated_to_latest`.
- Given a migration that fails, then the version and schema stay unchanged — `test_db.py::test_failed_migration_rolls_back`.
- Writes to one company go through one writer thread; reads use a pool and see committed data — `test_db.py::test_writes_run_on_one_thread`, `test_reads_see_committed_writes`.
- **A person in two companies sees only the chosen company's data; the files are separate** — integration `test_orgs.py::test_person_in_two_companies_sees_only_the_chosen_one`.
- A person who is not a member of a company gets 404 for it (never another company's file) — `test_orgs.py::test_non_member_cannot_open_company`.
- A slug that is not `[a-z0-9-]` (e.g. `../x`) is refused before any path is built — `test_orgs.py::test_bad_slug_is_refused`.

### M1-04 · Google sign-in (fake OIDC provider in tests)
- Workspace (`hd` set) and personal accounts with a matching person sign in; a session cookie (HttpOnly, Secure, SameSite=Lax) is set — `test_auth.py`.
- An account with no person and no invite is refused, redirected to the refusal page, and `signin.refused` is in the audit log.
- `email_verified=false`, wrong `aud`, wrong `nonce`, expired token, bad `state` → refused.
- A person found by `sub` signs in even when their email changed; email is used only when the person has no `sub` yet.
- Sign-out deletes the session row; the old cookie then gets 401.

### M1-05 · Invites, Origin, client IP
- An invite older than 14 days is refused at sign-in — `test_invites.py::test_expired_invite_is_refused`.
- A revoked invite is refused; a used invite cannot be used twice.
- A POST with a foreign `Origin` gets 403; a POST with no Origin gets 403 — `test_origin.py`.
- The audit log stores `CF-Connecting-IP` as the client IP.

### M1-06 · Admin console and company settings
- `tazko admin --email trungngo@hugepigstudio.com`, then sign-in reaches `/admin` — e2e `admin.spec.ts`.
- A non super admin gets 403 on `/admin/api/*`.
- Removing or demoting the last owner of a company is refused (KNOWN-DEVIATIONS #5); removing yourself asks first (UI).
- The company switcher lists only the person's companies.

### M1-07 · Company lifecycle
- Create makes the folder and database; suspend blocks sign-in and API access for its members; resume restores it; delete moves the folder to `trash/<slug>-<timestamp>/` — one test per state.

### M1-08 · Deploy
- A release whose `/health` fails rolls back to the previous release by itself — `deploy/backend/release.sh` dry run.
- `tazko backup` then `tazko check` on the snapshot succeeds; a corrupted file fails `check`.
- The other service on the host keeps running (owner checks).

## Open questions

- Q2 (M1-07): does the company switcher list a suspended company (greyed, "Suspended", not clickable) or hide it? Today `companies_of` returns it with its status and `open_company` refuses it. Proposed: list it as suspended, so members know why it is gone.
