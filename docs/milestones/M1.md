## Done when

Each line of the build plan's M1 section as scenarios, with the test that proves it.
Backend tests live under `backend/tests/`; e2e under `tests/e2e/`.

### M1-01 · Walking skeleton
- Given the API runs, when `GET /health`, then 200 `{"status":"ok"}` — integration `test_http.py::test_health_returns_200`.
- Given another origin, when a CORS preflight arrives, then no allow-origin header — `test_http.py::test_cors_ignores_other_origins`.
- The web page loads and reaches the API — e2e `health.spec.ts`.

### M1-02 · Config and commands
- Given `TAZKO_ENV=production` and no Google client id, when settings load, then the error names `TAZKO_GOOGLE_CLIENT_ID` — unit `test_config.py::test_production_requires_google_client`.
- Given production, when `TAZKO_PUBLIC_URL` or `TAZKO_WEB_ORIGIN` is not https, then a clear error — `test_production_requires_https_urls`.
- Given `TAZKO_SECRET` shorter than 32 characters, then the error names it — `test_short_secret_is_refused`.
- Given an empty `TAZKO_SECRET`, when the secret is first needed, then a random `secret` file (mode 600) is made in the data folder and reused afterwards — `test_secret.py`.
- Given `TAZKO_SMTP_HOST` without `TAZKO_MAIL_FROM`, then the error names `TAZKO_MAIL_FROM` — `test_smtp_needs_mail_from`.
- `tazko admin --email X` creates or promotes X to super admin and writes an audit row (lands with M1-03, which brings `control.db`) — `test_cli.py::test_admin_creates_a_super_admin`, `test_admin_promotes_an_existing_person`.
- `backup` and `check` exist and say they arrive in M1-08 — `test_cli.py::test_unfinished_commands_fail_with_the_task_id`.

### M1-03 · Databases
- Given a new data folder, when the app starts, then `control.db` exists at the latest `user_version` with WAL and foreign keys on — `test_db.py::test_new_database_is_migrated_to_latest`.
- Given a migration that fails, then the version and schema stay unchanged — `test_db.py::test_failed_migration_rolls_back`.
- Writes to one company go through one writer thread; reads use a pool and see committed data — `test_db.py::test_writes_run_on_one_thread`, `test_reads_see_committed_writes`.
- **A person in two companies sees only the chosen company's data; the files are separate** — integration `test_orgs.py::test_person_in_two_companies_sees_only_the_chosen_one`.
- A person who is not a member of a company gets 404 for it (never another company's file) — `test_orgs.py::test_non_member_cannot_open_company`.
- A slug that is not `[a-z0-9-]` (e.g. `../x`) is refused before any path is built — `test_orgs.py::test_bad_slug_is_refused`.

### M1-04 · Google sign-in (fake OIDC provider in tests)
- Workspace (`hd` set) and personal accounts with a matching person sign in; a session cookie (HttpOnly, Secure, SameSite=Lax) is set — `test_auth.py`.
- An account with no person and no invite is refused, redirected to the refusal page, and `signin.refused` is in the audit log.
- `email_verified=false`, wrong `aud`, wrong `nonce`, expired token, bad `state` → refused.
- A person found by `sub` signs in even when their email changed; email is used only when the person has no `sub` yet.
- Sign-out deletes the session row; the old cookie then gets 401.

### M1-05 · Invites, Origin, client IP
- An invite older than 14 days is refused at sign-in — `test_invites.py::test_expired_invite_is_refused`; one a moment inside 14 days works — `test_invite_a_moment_before_14_days_is_accepted`.
- A revoked invite is refused — `test_revoked_invite_is_refused`; a used invite cannot be used twice — `test_used_invite_cannot_be_used_twice`.
- An invited email signs in and joins the company, and finds themselves in the company file — `test_invited_person_signs_in_and_joins_the_company`, `test_invited_person_finds_themselves_in_the_company_file`.
- A POST with a foreign `Origin` gets 403; a POST with no Origin gets 403 — `test_origin.py::test_every_write_route_refuses_a_foreign_or_missing_origin`, and a new route is covered without asking — `test_a_new_write_route_is_checked_without_asking`.
- The audit log stores `CF-Connecting-IP` as the client IP — `test_invites.py::test_audit_log_stores_the_address_cloudflare_reports`; `TAZKO_HOST` must be loopback — `test_config.py::test_host_must_be_loopback`.
- WebSocket handshake Origin: no WebSocket exists yet; `require_same_origin` carries a TODO for M3-01.

### M1-06 · Admin console and company settings
- `tazko admin --email trantrungdng@gmail.com`, then sign-in reaches `/admin` — e2e `admin.spec.ts`.
- A non super admin gets 403 on `/admin/api/*`.
- Removing or demoting the last owner of a company is refused (KNOWN-DEVIATIONS #5); removing yourself asks first (UI).
- The company switcher lists only the person's companies.

### M1-07 · Company lifecycle
- Create makes the folder and database; suspend blocks sign-in and API access for its members; resume restores it; delete moves the folder to `trash/<slug>-<timestamp>/` — one test per state.

### M1-08 · Deploy
- A release whose `/health` fails rolls back to the previous release by itself — `deploy/backend/release.sh` dry run.
- `tazko backup` then `tazko check` on the snapshot succeeds; a corrupted file fails `check`.
- The other service on the host keeps running (owner checks).
- Rolling back after a release that migrated works: today `Database` refuses a file newer than the code, so the previous release cannot start. M1-08 adds a "readable by release ≥ N" mark per migration (expand-contract) or restores the pre-release backup automatically; test both paths (finding from the D18–D20 review).

## Carried from the security review (2026-11-16)

Each line becomes a test in its task.

- **M1-04 sign-in**
  - Every sign-in issues a fresh random session token; never accept one from the client; delete the old session on sign-in and sign-out. Cookie host-only (no `Domain`), HttpOnly, Secure, SameSite=Lax, ideally `__Host-` prefixed.
  - Match by `sub` first; by email only when `google_sub IS NULL`, through `users.service.normalize_email`. Never re-link a row that has a `sub`; never change a stored email to one another row has. Audit-log the first link of a `sub` (the super admin row from `tazko admin` has none until then).
  - Require `email_verified`; verify state, nonce and PKCE; redirect only to `TAZKO_WEB_ORIGIN`, never to a URL from the request.
  - Sessions of disabled people are refused; `open_company` checks `users.disabled_at` too.
  - Access log: uvicorn logs query strings (`/auth/google/callback?code=...`). Turn the access log off or strip query strings.
  - Done in M1-04: all of the above. e2e covers the screens only; a full browser round trip needs a fake OIDC server, which M1-06 brings for `admin.spec.ts`.
  - Add `CompanyDep` in core/deps.py (slug from the path + signed-in person → `open_company`); tests/unit/test_architecture.py keeps every other way out.
- **M1-05 Origin and invites**
  - Origin must equal `TAZKO_WEB_ORIGIN` exactly: SameSite=Lax does not stop other `*.hugepigstudio.com` sites (same-site), including the other service on the host. Refuse writes with no Origin (except `/api/v1` bearer calls later) and check the WebSocket handshake the same way.
  - Accept an invite in one `write()`: `expires_at > now`, not accepted, not revoked, then set `accepted_at`. Match on the normalized email.
  - Trust `CF-Connecting-IP` only because the server listens on loopback; keep `TAZKO_HOST` loopback-only.
  - Done in M1-05: all of the above except the WebSocket handshake, which waits for the first WebSocket (M3-01).
- **M1-06 admin and members**
  - `create_company`, `add_member` and every later service check the actor (super admin or company owner) inside the service, not in the route.
  - Super admin can remove a recorded Workspace domain (`workspace_domains`, D26) for a company that left Google Workspace; until then a row is only removed by hand.
  - `upsert_member` silently changes an existing member's role: changing or removing the last owner must be refused there (KNOWN-DEVIATIONS #5).
- **M1-08 deploy**
  - `/etc/tazko/tazko.env` must set `TAZKO_ENV=production` (it switches off `.env` reading and turns on the production checks). Do not copy `.env.example`'s development value.
  - Units: `UMask=0077`, `WorkingDirectory=/var/lib/tazko`. setup-host.sh makes `/var/lib/tazko` and `/var/backups/tazko` `tazko:tazko` mode 700.
  - Backups contain `data/secret`: keep them mode 600/700 and treat the off-machine copy as secret, or leave the secret out and document re-creating it (signs everyone out).
- **Web (first screen with headers)**: Content-Security-Policy in frontend/public/_headers with `connect-src` set to the API host. Done in M1-04; M1-08 (deploy/frontend) keeps it in step with the API host.
